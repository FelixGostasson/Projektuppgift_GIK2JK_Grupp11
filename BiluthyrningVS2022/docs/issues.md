# Spårning mot issues

Arbetet redovisas med faktiska ändringar, utan ändrade skapandedatum eller påstådda gruppaktiviteter.

| Issue | Underlag och läge |
|---|---|
| #1 Repo och åtkomst | Forken finns. Alla gruppmedlemmars och lärarnas åtkomst måste fortfarande bekräftas. |
| #2 GitHub Projects | Ingen tavla har skapats/verifierats av denna körning. Anslut issues till en tavla med To Do, In Progress och Done. |
| #3 Kravanalys | krav.md: kravlista, avgränsningar, antaganden och öppna frågor. |
| #4 User Stories | krav.md: fem berättelser med acceptanskriterier. |
| #5 Use Cases | krav.md: söka, boka, avboka, hämta ut och återlämna. |
| #6 Use Case-diagram | use-cases.puml; inkluderar aktörer, tillgänglighet och prisberäkning. |
| #7 Domänklasser | Doman.cs samt ansvarstabellen i design.md. |
| #8 Domänmodell | klassdiagram.puml med relationer, multiplicitet, interface och arv. |
| #9 Kodstruktur | Separata ansvarsområden, lösning, gitignore och bygg-/körinstruktioner. Gruppens lokala körning är ännu inte bekräftad. |
| #10 Fordon | Abstrakt basklass, fyra typer och validering; testade via samma bokningsmotor. Modellen är ett granskningsförslag, inte ett påstått gruppbeslut. |
| #11 Bokningsmotor | Boka, sök, avboka och statusåtgärder; regler och begränsningar dokumenterade. |
| #12 Tillgänglighet | Exklusivt slutdatum, överlappsregel, historik och verifieringsexempel i design.md och tester. |

Föreslagen planering framåt: granska krav/modell tillsammans, verifiera körning hos alla, ordna tavla och läraråtkomst, skapa presentation, öva två fristående demonstrationer och ett integrerat scenario. Gruppen väljer ansvariga; inga personer tilldelas utan underlag.
